# FitLog AI — WBS (Work Breakdown Structure) 및 일정

본 프로젝트는 7주 일정으로 진행되며, 각 주차별 작업 항목과 진행 상태는
다음과 같다. 7주차(오늘)는 최종 발표 주차이다.

## 전체 일정 개요

| 주차 | 주요 목표 | 상태 |
|------|-----------|------|
| 1주차 | 프로젝트 기반 세팅 | 완료 |
| 2주차 | 입력 폼 설계 (목표/경험/부위 등) | 완료 |
| 3주차 | 점진적 과부하 분석 · 피드백 설계 | 완료 |
| 4주차 | AI 기반 1주 루틴 생성 (핵심 기능) | 완료 |
| 5주차 | 저장·이력 관리 (routines.json, 이미지 매핑) | 완료 |
| 6주차 | 문서화 · 테스트 · GitHub 배포 | 완료 |
| 7주차 | 최종 발표 준비 및 시연 | 완료 |

## 주차별 세부 WBS

### 1주차 — 기반 세팅
- 프로젝트 초기 구조 (package.json, tsconfig.json) 구성
- Gemini API 연동 기본 구조 작성
- 루틴 생성 프롬프트 1차 작성

### 2주차 — 입력 폼 설계
- 운동 목표(벌크업/다이어트/체력유지) 선택 UI
- 경험 수준(초보/중급/고급), 주당 운동일수(2~7일) 입력
- 집중 부위(상체/하체/전신), 신체정보(키/몸무게, 선택) 입력
- 추가 요구사항(자유 텍스트, 선택) 입력 필드

### 3주차 — 분석 · 피드백 설계
- 점진적 과부하(progressive overload) 반영 로직 설계
- 운동별 세트×횟수, 휴식시간 표시 설계
- 하루 총 운동 예상시간·종목수·총 세트 계산 로직 설계

### 4주차 — 핵심 기능: AI 기반 1주 루틴 생성
- 입력값 기반 AI 프롬프트 설계
- 점진적 과부하를 반영한 1주 루틴을 JSON으로 생성
- Express 기반 웹 서버 및 폼 UI 구현
- 환경변수(.env) 기반 API 키 관리 적용

### 5주차 — 저장·이력 관리
- routines.json 저장/조회 구현 (최대 20개, 초과 시 오래된 것 자동 삭제)
- 운동별 수행 무게(kg) 기록 기능
- 이전 루틴 목록 조회 및 삭제 기능
- 접속 시 오늘 요일 탭 자동 반영
- 운동별 이미지(머신·동작) 매핑
- 다음 주 루틴 생성: 이전 루틴의 수행 무게 기록을 AI 프롬프트에 포함해
  점진적 과부하 반영, 입력값 재설정 가능하도록 구현

### 6주차 — 문서화 · 테스트 · 배포
- README, AGENTS.md 작성
- ADR, 아키텍처, 기획서, WBS, SETUP 문서 작성
- Jest 기반 단위 테스트(db.test.ts), 통합 테스트(web.test.ts) 작성 및 PASS 확인
- GitHub에 소스코드 및 문서 push

### 7주차 — 최종 발표
- 발표 슬라이드(비전, 아키텍처, ADR, WBS, 시연 데모 등) 완성
- 5분 발표 스크립트 작성 및 리허설
- 시연 데모 시나리오 점검

## 일정 관리 방식

각 주차 작업은 GitHub 커밋 단위로 추적되며, 주요 마일스톤은 위 표의
주차별 목표를 기준으로 점검한다.
