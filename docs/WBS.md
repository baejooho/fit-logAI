# FitLog AI — WBS (Work Breakdown Structure) 및 일정

본 프로젝트는 6주 일정으로 진행되며, 각 주차별 작업 항목과 진행 상태는 다음과 같다.

## 전체 일정 개요

| 주차 | 기간 | 주요 목표 | 상태 |
|------|------|-----------|------|
| 1주차 | Week 1 | 프로젝트 기반 세팅 | 완료 |
| 2주차 | Week 2 | 운동 기록 입력 기능 설계 | 완료 |
| 3주차 | Week 3 | 점진적 과부하 분석 · 피드백 설계 | 완료 |
| 4주차 | Week 4 | AI 기반 1주 루틴 생성 (핵심 기능) | 완료 |
| 5주차 | Week 5 | 웹 UI 구현 | 완료 |
| 6주차 | Week 6 | 문서화 · 배포 · 발표 준비 | 완료 |

## 주차별 세부 WBS

### 1주차 — 기반 세팅

- 프로젝트 초기 구조 (package.json, tsconfig.json) 구성
- AI API 연동 기본 구조 작성
- 루틴 생성 프롬프트 1차 작성

### 2주차 — 기록 기능 설계

- 운동 기록 입력 흐름 설계
- 이전 기록 조회 및 비교 로직 설계
- 오늘 목표 자동 제안 로직 설계

### 3주차 — 분석 · 피드백 설계

- 점진적 과부하(progressive overload) 감지 로직 설계
- 주간 볼륨 시각화 설계
- AI 피드백 멘트 생성 프롬프트 설계

### 4주차 — 핵심 기능: AI 기반 1주 루틴 생성

- 목표/경험/운동일수 입력 기반 AI 프롬프트 설계
- 점진적 과부하를 반영한 1주 루틴을 JSON으로 생성
- Express 기반 웹 서버 및 폼 UI 구현
- 생성 결과 웹 화면에 표 형태로 출력
- 환경변수(.env) 기반 API 키 관리 적용
- API 호출 비용 최소화를 위해 생성 범위를 1주 단위로 설계

### 5주차 — 웹 UI 고도화

- 결과 화면 UI/UX 개선
- 입력 폼 유효성 검사
- 반응형 레이아웃 적용

### 6주차 — 문서화 · 배포 · 발표

- README, AGENTS.md 작성
- ADR, 아키텍처 문서 작성
- SETUP/DEPLOY/TESTING 가이드 작성
- 최종 발표 자료 준비 및 데모 리허설

## 참고

초기 설계에서는 4주 점진적 과부하 플랜을 일괄 생성하고 SQLite에
저장하는 구조를 고려했으나, API 토큰 사용량 및 개발 기간을 고려하여
1주 단위 루틴 생성 + Stateless(DB 미사용) 구조로 범위를 조정했다.

자세한 배경은 [ADR-2, ADR-3](ADR.md)을 참고한다.
