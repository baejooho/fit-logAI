# FitLog AI — 아키텍처 설계 문서

## 1. 개요

FitLog AI는 사용자의 입력(목표, 경험, 부위, 신체정보, 추가요구사항)을
받아 Gemini API에게 전달하고, 점진적 과부하가 반영된 1주 운동 루틴을
생성하여 웹 화면에 표시하는 Express 기반 웹 애플리케이션이다.

생성된 루틴과 사용자가 기록한 수행 무게는 routines.json 파일에
저장되며, 다음 주 루틴 생성 시 이 기록을 AI 프롬프트에 포함하여
점진적 과부하를 자동으로 반영한다.

## 2. 시스템 구성도

    [사용자]
       | 1. 목표/경험/부위/신체정보/요구사항 입력
       v
    [FitLog AI 서버 (Express)]
     +- 입력 폼 (web.ts)
     +- 프롬프트 빌더 (claude.ts)
     |     | 2. 프롬프트 전송 (이전 루틴의 수행 무게 포함 시 점진적 과부하 지시)
     |     v
     |  [Gemini API (gemini-2.5-flash)]
     |     | 1주 루틴 JSON 반환
     |     v
     +- 이미지 매핑 (운동명 -> 사전 제작 이미지)
     +- 결과 렌더러 (요일별 탭, 세트x횟수, 휴식시간, 총 운동시간/종목수/세트)
     |     | 4. 수행 무게(kg) 입력 -> 저장
     |     v
     +- 저장소 (db.ts) ---- routines.json (최대 20개, FIFO 삭제)
            ^
            | 3. 다음 주 루틴 생성 시 이전 루틴 + 수행 무게 기록을 읽어
            |    프롬프트에 포함 (점진적 과부하 반영)
            +---------------------------------------------

## 3. 컴포넌트 설명

### 3.1 입력 폼 (web.ts)
- 목표/경험/운동일수/집중부위/신체정보/추가요구사항을 입력받는 화면
- 저장된 이전 루틴 목록을 함께 표시, 다음 주 루틴 생성 시 입력값 재설정 가능

### 3.2 프롬프트 빌더 (claude.ts)
- 사용자 입력값으로 프롬프트를 구성
- 다음 주 루틴 생성 시, 이전 루틴의 운동별 수행 무게(kg) 기록을
  프롬프트에 포함하여 "점진적 과부하" 반영을 AI에 명시적으로 지시

### 3.3 AI 연동 (Gemini API)
- @google/generative-ai로 gemini-2.5-flash 호출
- API 키는 환경변수(GEMINI_API_KEY)로 관리

### 3.4 이미지 매핑
- AI가 반환한 운동명을 사전 제작된 운동별 이미지(머신·동작)에 매핑

### 3.5 결과 렌더러
- 요일별 탭 UI로 운동 이미지, 세트×횟수, 휴식시간 표시
- 하루 총 운동 예상시간, 종목수, 총 세트 표시
- 수행 무게(kg) 입력 필드 제공

### 3.6 저장소 (db.ts)
- routines.json에 fs.readFileSync/writeFileSync로 읽기/쓰기
- 루틴 + 수행 무게 기록을 함께 저장, 최대 20개, 초과 시 오래된 것부터 삭제
- 접속 시 오늘 요일에 해당하는 탭 자동 선택
- 이전 루틴 목록 조회 및 삭제 기능 제공

## 4. 데이터 흐름

1. 사용자가 입력 폼에서 목표/경험/부위 등 입력 후 "새 루틴 생성하기"
2. 서버가 프롬프트 구성 후 Gemini API 호출 -> 1주 루틴 JSON 수신
3. 운동명을 이미지에 매핑, 요일별 탭으로 렌더링
4. 사용자가 각 운동의 수행 무게(kg)를 기록 -> routines.json에 저장
5. 다음 주, "다음 주 루틴 생성하기" 클릭 시 입력값 재설정 가능
6. 서버가 이전 루틴의 수행 무게 기록을 프롬프트에 포함하여 Gemini 호출
7. AI가 점진적 과부하(무게/세트/횟수 증가)가 반영된 새 1주 루틴 생성

## 5. 설계상 특징

- 점진적 과부하 자동화: 수행 무게 기록이 다음 루틴 생성의 입력이 되는
  피드백 루프 구조
- API 비용 효율성: 1회 요청당 1주 루틴만 생성하여 토큰 사용량 최소화
- 경량 저장소: 1인 사용 환경에 맞춰 SQLite 대신 JSON 파일 사용
- 환경변수 기반 설정: API 키 등 민감 정보는 .env로 분리 관리

## 6. 향후 확장 시 아키텍처 변화

- 다주차 플랜 확장 시: 1주 루틴 + 수행 무게 기록을 누적하여 4주 단위
  점진적 과부하 플랜으로 발전
- 데이터 증가 시: routines.json -> SQLite로 저장소 교체 (db.ts 모듈만 교체)
