# AGENTS.md — AI 에이전트 활용 정책 및 워크플로우

본 문서는 FitLog AI 프로젝트 개발 과정에서 AI 에이전트(Claude Code)를
활용한 워크플로우와 코딩 정책을 기록한다.

## 1. 사용한 AI 에이전트

- **Claude Code** (터미널 기반 AI 코딩 에이전트): 프로젝트 구조 생성,
  코드 작성/수정, 패키지 설치, 디버깅에 활용
- **Claude (대화형)**: 발표 자료 기획, 문서(README, ADR 등) 작성,
  설계 방향 의사결정 보조에 활용

## 2. AI 에이전트에게 위임한 작업

| 작업 | 위임 여부 | 비고 |
|------|-----------|------|
| 프로젝트 초기 구조 생성 (package.json, tsconfig.json) | 위임 | Claude Code가 생성 |
| AI API(Gemini) 연동 코드 작성 | 위임 | 모델명 변경 등 디버깅 포함 |
| Express 웹 서버 및 폼 UI 구현 | 위임 | 입력 → 결과 출력 흐름 구성 |
| 프롬프트 설계 (1주 점진적 과부하 루틴 생성) | 협업 | 방향 결정은 직접, 세부 문구는 AI 작성 |
| 버그 수정 (모델 404, 한글 URL 인코딩 오류 등) | 위임 | 에러 메시지를 AI에게 전달하여 수정 |
| 문서화 (README, ADR, WBS, ARCHITECTURE, SETUP) | 위임 | 프로젝트 정보를 기반으로 AI가 작성 |

## 3. 개발 워크플로우

1. 기능 요구사항을 자연어로 AI 에이전트에게 전달
2. AI가 코드를 생성/수정
3. `npm run web`으로 직접 실행하여 동작 확인
4. 에러 발생 시 에러 메시지를 그대로 AI에게 전달하여 반복적으로 수정
5. 동작이 확인되면 Git에 커밋

## 4. 코딩 정책

- **언어**: TypeScript 사용 (타입 안정성 확보)
- **민감 정보 관리**: API 키 등은 `.env`로 분리, `.gitignore`에 포함
  (`.env.example`로 필요한 변수 안내)
- **AI 모델 교체 용이성**: AI 호출 로직을 별도 모듈로 분리하여, 추후
  다른 LLM API로 교체 시 영향 범위를 최소화
- **점진적 개발**: 4주 플랜 → 1주 루틴, DB 포함 → DB 제거 등 범위를
  축소하며 핵심 기능의 완성도를 우선하는 방식으로 진행 (자세한 배경은
  [docs/ADR.md](docs/ADR.md) 참고)

## 5. 향후 AI 활용 개선 방향

- 단위/통합 테스트 코드 작성에 AI 에이전트 활용 확대
- 코드 리뷰 단계에서 AI 기반 정적 분석 도입 검토
