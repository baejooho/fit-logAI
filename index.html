💡 선택 이유 — 카드 등록 없이 무료로 사용 가능한 Gemini API (2.5-flash)를 AI 엔진으로 선택(ADR-1). 응답 토큰 절약을 위해 1주 단위 루틴 생성 방식 채택(ADR-2), 1인 사용 환경에 맞춰 SQLite 대신 JSON 파일(routines.json) 저장 방식으로 설계(ADR-3).
📌 ADR — 주요 의사결정 기록
ADR-1
Gemini API 선택
배경유료 LLM API는 사용량 기반 과금, 결제수단 등록 필요해 학습용 프로젝트엔 부담
결정카드 등록 없이 무료 발급 가능한 Gemini API (gemini-2.5-flash) 사용
결과비용 부담 없이 개발·데모 가능, 호출 모듈 분리로 교체 용이
ADR-2
1주 루틴 생성 방식
배경4주 플랜 일괄 생성 시 응답 토큰 ↑, 무료 티어 제한 우려
결정1회 호출당 1주 점진적 과부하 루틴 생성
결과응답 속도 개선, 추후 반복 호출로 다주차 확장 가능
ADR-3
SQLite 대신 JSON 파일 저장
배경1인 사용 프로젝트에 SQLite 등 별도 DB 설치·스키마 관리는 과한 엔지니어링
결정routines.json 파일에 fs.readFileSync/writeFileSync로 읽고 쓰기 (최대 20개, 오래된 것 자동 삭제)
결과설치 없이 즉시 동작, 동시접속 없는 1인 환경에 적합. 검색·동시성 필요해지면 SQLite로 전환 가능
🔧 구현 시행착오 & 개발 환경
⚠️ 문제 1 — API 모델 404 에러
gemini-1.5-flash 모델이 v1beta에서 404 Not Found. AI 모델 버전이 빠르게 바뀌어 사용 가능한 모델명을 직접 확인해야 했음.
✅ 해결 — ListModels로 사용 가능 모델 확인 후 gemini-2.5-flash로 교체
⚠️ 문제 2 — 다음 주 루틴 설정 미반영
"다음 주 루틴 생성"에서 목표·경험·부위 등을 새로 선택해도 반영되지 않음. 이전 루틴의 설정값을 그대로 복사해 새 폼 데이터를 덮어쓰는 구조가 원인.
✅ 해결 — 새로 입력한 폼 값을 우선 적용하고, 비어있는 값만 이전 루틴에서 채워오도록 로직 수정
⚠️ 문제 3 — 추가 요구사항 미반영
"무릎 부상으로 스쿼트 대신 다른 운동" 같은 자유 텍스트 요구사항을 입력해도 AI가 무시하고 기존 운동을 그대로 추천하는 경우 발생.
✅ 해결 — 프롬프트에서 추가 요구사항을 별도 섹션으로 분리하고 "반드시 반영" 문구로 강조
